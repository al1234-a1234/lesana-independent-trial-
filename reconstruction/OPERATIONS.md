# التشغيل والصيانة

## بيئة التشغيل

Node.js 24.x فقط كما في engines، وقرص قابل للكتابة. استخدم `npm ci` للحزم المقيدة في lockfile، ثم `npm run build` و`npm start`. Next.js يطبع تحذيرًا عن Node SQLite experimental؛ هذه وحدة Node المضمّنة ولا تتطلب خادم DB أو compilation لحزمة SQLite.

المتغيرات الاختيارية في `.env.example`:

| المتغير | الوظيفة |
|---|---|
| `SAT_DATABASE_PATH` | ملف SQLite؛ الافتراضي `private-data/satr.sqlite` |
| `APP_ORIGIN` | الأصل العام المسموح لـPOST، مثل `https://learn.example`؛ اضبطه عند وجود reverse proxy |
| `NEXT_TELEMETRY_DISABLED=1` | تعطيل قياس Next.js أثناء البناء والتشغيل |

لا تستخدم نفس ملف SQLite لبيئات اختبار وتطوير وإنتاج مختلفة. لا توجد متغيرات `NEXT_PUBLIC` تحوي أسرارًا. تغيير ملف env يتطلب إعادة تشغيل الخدمة.

## الحاوية الاختيارية

```bash
docker compose up --build
```

افتح `http://localhost:3000`. عند استخدام عنوان مختلف مرّر `APP_ORIGIN` الموافق له. التخزين named volume باسم `satr-data`، ومستخدم الحاوية node. ملفات Docker وcompose مُسلّمة كمسار نشر مقترح؛ لم يُبنَ Docker image في بيئة التسليم. الاختبارات الفعلية جرت على Node مباشرة.

## إضافة قصة أصلية

أضف عنصرًا إلى `content/stories.json`: slug فريد وحروف آمنة صغيرة/شرطات، وعنوانين ومستوى/theme ووصف، ثم أسطر text/ar/keyword. اكتب نصًا جديدًا تملكه. معرّف كل سطر يشتق من slug وموضعه؛ لا تعِد ترتيب أسطر مستخدمة دون ترحيل للتقدم المخزّن.

ثم:

```bash
npm run audio:generate
npm run test:unit
npm run build
npm run test:e2e
```

التوليد يحتاج FFmpeg مع `flite` و`ffprobe`. تحقق بـ`ffmpeg -filters` من وجود flite. ينشئ السكربت مؤقتًا ملفات نصية محلية ويولد صوت slt ويُخرج manifest بالبصمات والمدد. لا ينزل أصواتًا أو يتصل بمزوّد. جودة الصوت بسيطة؛ استبدال MP3 يدويًا أو عبر حساب خدمة خاص جديد ممكن، لكن لا يوجد موصل Polly/R2 منفّذ أو مفاتيح لازمة هنا.

تغيير المحتوى يغيّر أعداد القصص والأسطر؛ بعض نصوص Dashboard الحالية مثل إجمالي 18 و3 قصص ثابتة للنسخة المسلّمة وتحتاج تحديثًا عند التوسع. `catalog.ts` نفسه يشتق الأسطر ديناميكيًا.

## النسخ الاحتياطي

أوقف العملية قبل نسخ ملف SQLite وحده، أو استخدم واجهة backup متسقة في SQLite. في وضع WAL لا تعتمد على نسخ ملف `.sqlite` أثناء تشغيل الكتابات وترك WAL خلفه. احتفظ بنسخ خارج المضيف وجرّب الاستعادة على مسار تجريبي. لم تُنفّذ سياسة نسخ احتياطي سحابية تلقائية.

## المراقبة والحدود

تابع أخطاء POST، وعدد العناصر المعلقة وحجم القرص وزمن الطلبات. تخزين المحاولات ينمو؛ حدد سياسة احتفاظ لا تكسر idempotency للمحاولات القديمة التي قد تصل متأخرة. لا يوجد cron مطلوب للمراجعة؛ dueAt يُحسب عند المحاولة، والاستحقاق يُقرأ عند فتح الصفحة.

## إعادة الفحص

`npm run typecheck` و`npm run test:unit` ثم build وPlaywright. تستعمل اختبارات E2E قاعدة `.test-data/e2e.sqlite` وتعيد تهيئتها تلقائيًا، ولا تمس `private-data/satr.sqlite`. اختبار المراجعة يضبط موعد سجل خاص في قاعدة الاختبار فقط لكي لا ينتظر يومًا فعليًا؛ لا يوجد endpoint لتعديل الساعة أو الموعد في المنتج.
